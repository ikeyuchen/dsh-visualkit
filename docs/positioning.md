# 定位：视觉设计工具箱（Visual Design Toolkit）

> 一句话：给工具和框架，不给风格目录——同一套原语可以落成 UI 界面、网页、平面图、海报或纯文字版式，风格由使用者组合。它同时是一件"量 AI 味"的尺子：把模板化的视觉选择数出来。

## 名字：为什么是「视觉」

| 候选 | 词义覆盖 | 天然排除 | 用户会期待什么 |
|---|---|---|---|
| **美术**设计 | 造型、作图、物料制作 | 偏"手上功夫"与教学语境 | 一个帮我画图的工具 |
| **艺术**设计 | 最宽（向外延伸到观念、表演） | 强调创作与原创表达 | 一个帮我产创意的工具 |
| **视觉**设计 | 一切"看得见的设计产出" | 非视觉门类（声音/叙事/流程） | 一个把视觉产出做成、验好的工具 |

「美术设计」会被当成画图工具，而本包不生成图（图标是检索来的真资产，渲染只把已有内容落成像素）；「艺术设计」暗含观念与原创，与"风格由使用者组合"的立场不符；「视觉设计」与能力边界逐项对齐，代价是最通用、品牌区分度最弱。英文取 **Visual Design Toolkit**，包 id 固定为 **`dsh-visualkit`**：发出去再改名会断引用、破坏已安装用户。

## 命名轴：按「回答什么问题」，不按「输入是什么」

场景（UI/网页/平面/海报/排版）与输入介质（源码/矢量/位图）都是**参数**，工具名只回答"它能替你回答什么问题"。

现有工具名都已是问题导向（`layout_check` / `design_style` / `design_render` / `icon` / `morph`），只解释一处：`taste_check` 不叫 `ui_check`，因为 `ui_` 会把海报/图片排除在外，而"像不像 AI"在它们身上同样成立。同一个问题换输入介质，是入口里多一种介质（源码或 PNG），而不是多一个工具——每多一个工具都是每请求常驻 token。

新增能力的落位规则：新**问题** → 新工具（像不像 AI、排版对不对、用什么手段、出什么成品）；新**场景**或新**输入介质** → 现有工具的参数（位图、SVG、HTML）；只服务单一场景的工具名 → 改名。

## 工艺链（四段）

取真资产（`icon` / `design_render asset`）→ 定规格（`design_style`：token + 骨架 + 交互）→ **量审美**（`taste_check taste` / `layout_check`）→ 出成品（`design_render` / `morph preview`）。其中最容易忽略的是 **AI 感**：模型不缺产能，缺美术判断，于是默写成紫渐变 + 大圆角 + 三张同构卡片 + "立即开启你的…之旅"。`taste_check taste` 把这类默认选择拆成 21 项可数指标，只在**成组出现**时归因为"模板感"——单项风格元素证明不了什么，措辞也不判定作者。

## 一份框架 × 多个场景

"我要做苹果风格的某某"：风格是同一个，落地的交付物不是。工具链按场景换组合，底层原语不变。

| 场景 | 主要工具组合 | 交付物 | 该场景真正的硬约束 |
|---|---|---|---|
| **UI 设计**（软件界面） | `design_style` (css/json/tailwind) → `icon` → `design_render html` → `layout_check ui` | token 表 + 组件骨架 + 界面截图 | 交互态齐全、字号梯级、信息密度、可点击元素有结果 |
| **网页设计** | `design_style` + `design_render html/fullPage` + `layout_check ui,render` | 页面截图 + 断点行为 | 首屏层级、真实渲染对比度、响应式不塌 |
| **平面设计**（封面/图形） | `design_render render` (SVG→PNG, 多尺寸/ICO) + `asset` + `composite` | 成品位图/矢量 | 边距、密度、视觉重心、单张可读性 |
| **海报设计** | `icon` (emit raw) + `design_render render` + `layout_check svg` | 成品 SVG/PNG | 文字几何（层级/行距/边距/溢出）、缩放后仍可读 |
| **文本类排版** | `design_style` (typeScale) + `layout_check svg/ui` | 版式规格（字号/行高/行长/对齐） | 行长 45–75 字符、行高与字号成比例、段落呼吸 |
| **交互/动效** | `design_style format=motion` + `morph` | 交互原语层 CSS + 形变预览 | 有物理反馈、`:focus-visible` 可达、`prefers-reduced-motion` 兜底 |
| **已有产出的体检**（任意场景） | `taste_check taste` + `layout_check` | AI 味分数 + 排版分数 + 返工清单 | 成熟产品的分数应该明显低于模板页 |

同一个"苹果风"落到四个场景，差别只在取哪几个工具：× UI = 紧排大字 + 中性灰阶 + 8pt 网格 + 每控件三态；× 网页 = 同 token，但要 1440/768/375 三个宽度的截图佐证；× 海报 = 同 token，字距只在大字号放开，留白 ≥ 单侧 8%；× 文本 = 同 token，只用字号/行高/字距，不用阴影和圆角。

## 为什么同一套能通用

"风格"在实现层面拆到底，只有这些手段：

| 原语 | 表达式 | 载体 |
|---|---|---|
| 色彩 / 明暗 | 10 个颜色 token，值可以是任意 CSS（含渐变） | `design_style tokens` |
| 字体 / 字号梯级 | 4 档字号 + 字体栈 + `tracking` 字距 | 同上 |
| 圆角 / 边线 | `radius` `border` `double`（双线）`organic`（有机圆角） | 同上 |
| 形状 / 图案 | `clip`：`polygon()` / 任意 `clip-path`；`pattern`：`repeating-*-gradient` 拼波点、斜纹、网格 | 同上 |
| 栅格 | `grid`：等宽 / Bento 不等宽 / 杂志穿插 | 同上 |
| 动效 | `dur` `ease` + `format=motion` 的 8 个交互原语 | 同上 |
| 素材 | 2029 lucide + 6302 tabler 图标、221 项内置素材 | `icon` / `asset` |

这 8 类之外的东西（组件行为、内容组织、品牌资产）属于项目规范，不该由工具决定。

## 有意不做的事

| 不做 | 原因 |
|---|---|
| 24 种风格的内置目录 | 目录一旦存在就会被当成模板，换项目就废；要的是"能表达"，不是"给一堆选" |
| 组件库（按钮/表格/弹窗的成品代码） | 每个项目的组件约定不同，交出去就是负债；给 token 与结构配方，让它长在项目自己身上 |
| 项目管理 / 需求拆解 | 与本插件职责无关 |
| 联网取图 / 云模型 | 全部本地离线，是可复现的前提 |

新功能该不该加：三个问题全部答"是"才加：① 换一个项目、换一个场景，它还有用吗（原语 vs 一次性）② 它提供的是**手段**还是**结果**（成品风格不行）③ 它能不能被验收（`layout_check` / `taste_check` 量得出来，或有明确的通过标准）。
