# AI 味：`taste_check taste`

范围：AI 味评分的 21 项指标、位图层的像素判据、分数口径，以及为什么只在「成组出现」时归因。排版体检见[排版规则](layout-rules.md)。

风格识别口径参考 [AI 味儿图鉴](https://vibe-hub.org/anti-ai-flavor)：中文口癖 11 条、页面模板感 8 条、不好用的交互 6 条，每条给原例与改法。`taste_check taste` 的 21 项指标覆盖其中多数视觉项（紫渐变 / 居中大标题 / emoji 图标 / 圆角阴影 / 玻璃拟态 / 渐变文字 / 文案口癖），另补六条页面与交互项：

| 规则 | 判据 |
|---|---|
| `nest-boxes` 框里再套框 | 三层以上圆角容器链（两层是正常的卡片 + 内部区块） |
| `divider-sprawl` 分割线泛滥 | ≥8 处 1px border-top/bottom 或 `<hr>` |
| `big-black-tight` 又大又黑又挤 | 同一条规则里 ≥30px + 字重 ≥700 + 行高 ≤1.25 |
| `dead-button` 按钮没结果 | ≥2 个 `<button>` 无 submit / 点击绑定 / data-action |
| `icon-tile-uniform` 图标色块一律 | ≥3 个同类图标块，且 CSS 里宽高 32–64px、圆角 ≥12px、背景是渐变（三项取交集） |
| `eyebrow-spam` 小标签逐段开场 | ≥4 个 eyebrow/kicker 类小标签；0–1 个是正常编辑手法，不报 |

判断原则：单个词、视觉元素或交互问题不能证明作者；看它是否与其他默认选择成组出现。单看每条都不致命，命中三项以上，用户就会认为这是 AI 做的。

## 分数口径

21 项指标分 `quality` / `style` / `content` 三层，三档 `profile`（`balanced` / `strict` / `structure`）用不同权重计分，分母不同，**分数不可跨 profile 比较**。

只在 `ai-tinged`（有 AI 味）与 `ai-default`（模板感明显）提示返工；`clean` 区间输出「stop optimizing here」——继续压分只会把设计推向安全区（Goodhart）。规则与检测同源：`lib/rules.js` 一份定义同时供 `design_style` 的约束文案与 `taste_check` 的检测器，避免约束改了检测没改。

## 位图层：手里只有一张图时也能判

`taste` 收位图时换一套像素层判据：PNG 直读，JPEG / WebP 由本机浏览器转码，像素解码器本身零外部进程。

| 判据 | 量什么 |
|---|---|
| `img-indigo-hue` 紫蓝相主导 | 有色像素里落在 238–300° 的比例（下界不降到 210–235：那是真实产品最常用的蓝） |
| `img-ramp` 大面积平滑渐变 | 3×3 区域里有多少是一维线性渐变 |

另有一项只量不判（进 `raw.cardGrid`，不计分）：`count` / `maxPerRow` / `equalWidth`。26 张 AI 制作的 UI 截图里只有 1 张是模板长相（紫蓝渐变营销页，52 分），其余 25 张得 0——0 不代表没问题，像素层看不见字号、间距、图标成套性、文案套路与交互态。

两条像素判据只给事实、不判分：同构三卡片（25 张合格界面里有 6 张满足，计分就是 6/25 误报）；中轴对称（三种量法都不成立）。合格产出上像素层分不出 AI 与人，所以结果固定带 `scope:` 与 `blind spots:` 两行：0 分不等于这张没问题，更不等于这不是 AI 做的。本节数字来自不入库的本机语料，无法由仓库复现。

## 三条纪律

每条都由误报校准：

| 纪律 | 为什么 |
|---|---|
| 只数风格指纹，不数通用质量缺陷 | 桌面应用本来就有 6 档小字号、7 个语义色；算进组合会把成熟产品判成模板 |
| 只数分值 ≥40 的项 | 单个 emoji（20 分）属于零星迹象，凑进三项就是噪音 |
| 措辞只说风格风险，不指认作者 | 「像套模板」不等于「这是 AI 做的」，后者不可证 |

刻意没做的三项：单字动作（收一下 / 提一层）要看词性；同一件事换名字要跨文件对齐；每处都加描述小字要 DOM 语义——都需要语义理解，规则做不准。
