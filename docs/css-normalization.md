# CSS 层：能机械到哪一步

范围：`css_edit` 的选型测量与边界。四个 action（`snap`、`scale`、`leading`、`radius`）的用法与保留规则见 `README.md`。

## `action=leading`：78 处选型

取 4 个真实项目的 **78 处** `line-height` 声明，模拟三种归并规则：

| 规则 | 改动 | 归一后 S3 剩余 |
|---|---|---|
| A 全部就近归并到 1.2、1.35、1.5、1.6、1.8 | 23% | **10 处（等于没改）** |
| **B 标题不动，正文死区抬到 1.5，≥1.5 就近归并到 1.5、1.6、1.8** | 23% | **2 处** |
| C 同 B，但标题也归并到 1.1、1.2、1.3 | 36% | 2 处 |

选 B。A 把值归到 1.35，而 1.35–1.5 正是 S3 的告警区；C 多改 56% 的声明，S3 剩余与 B 同为 2 处。

实现细节：标题级用 `h1–h6`、`.*title*`、`.*display*` 匹配，一律不动；平局取大，比较带 `1e-9` 容差（浮点下 `|1.6-1.7|` 与 `|1.8-1.7|` 差在 1e-16 量级，严格 `<=` 会把 1.7 判到 1.6）。

## `action=radius`：令牌化率决定收益

| 项目 | 可改 px | 已是 `var()` | 保留（%、0、999） |
|---|---|---|---|
| Colibri | 9 | 119 | 16 |
| Echo | 0 | 34 | 0 |
| Flow-Pilot | 1 | 7 | 0 |
| 旧版 0.5.4 | 124 | 0 | 47 |

三个现代项目的圆角已令牌化，可改的散落 px 只有个位数，改完外观几乎不变；手写时代的旧版 0.5.4 有 124 处可改。令牌化率 ≥50% 时 action 直接拒绝，并指向 `:root` 的 `--radius-*`。

Colibri 的输出是「已令牌化 82%（119/146 用 `var()`）」，其余为 16 处保留值、9 处散落 px 与 2 处其它圆角声明。旧版源码 0/171 未令牌化，散落值 6px×36、4px×33、3px×28，跑 `action=radius` 可改 11 处（`border-radius` 6px → 8px）。

## 还没做的两个候选

| 候选 | 机械逻辑 | 判断 |
|---|---|---|
| 过渡时长与缓动（`transition`、`animation`） | 把 `transition: X 180ms ease` 的时长收进 `120`、`160`、`240`、`320ms` 四档，判据取 `design_style format=motion` 的 `--t-fast`、`--t-base`、`--t-slow` 阶梯 | 风险低，无法用静态体检验收，只能人看 |
| `z-index` 归一 | 扫数值重排成 `10`、`100`、`1000` 三档并保持相对顺序 | 收益低、风险高（改错会破叠层），不建议做 |

## 明确不做（跨维度判断）

| 候选 | 为什么不做 |
|---|---|
| 色相家族收敛（11 族 → 4 族） | 哪些颜色是品牌色、哪些是随手加的高饱和色，只有人知道；工具能报（`hue-sprawl`），不能改 |
| 配色取向（冷暖、明度阶梯） | 设计决策，不是规范背离 |
| 组件形态（卡片、表格、列表） | 信息结构问题，`layout_check` 只该报，不该动 |
| 阴影方向统一 | `S11` 能报「有上有下」，哪边是正确光源取决于设计意图 |

这四项都在多个维度之间做取舍；机械化的前提是在同一维度内取更接近的值。

## 判断新动作该不该加

三个问题全部答「是」才做：只在一个维度内归并；改完能被现有工具验收（`layout_check` 规则或渲染 diff 拦得住）；默认值不替用户做风格决定。

按这三条：`leading` 合格；`radius` 勉强（需显式开启）；过渡时长合格但只能人看；`z-index` 不合格。
